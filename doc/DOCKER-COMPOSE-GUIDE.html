Paperclip · lokale Installation

Paperclip mit Docker Compose lokal starten

Schritt-für-Schritt: Image bauen, Compose-Stack starten, Instanz freischalten, Onboarding-Wizard mit der neuen OpenCode-Go-Anbindung durchlaufen, Daten und Betrieb im Alltag verwalten.
Stand: 5. Oktober 2026 · Basis: Repo-Quellcode (Branch master), docker/docker-compose.quickstart.yml, docker/docker-compose.yml, doc/DOCKER.md
0

Voraussetzungen

  • Docker 24+ mit Compose v2+ (im vorliegenden Setup: Docker 29, Compose v5).
  • Freie Ports: 3100 (Quickstart) bzw. 3100 und 5432 (Full Stack mit PostgreSQL).
  • openssl zum Erzeugen der Secrets.
  • Für den Onboarding-Test mit OpenCode Go: ein OpenCode-Go-API-Key aus der OpenCode Console (Abo Go oder Go Plus).
  • Ausgehendes Internet aus dem Container heraus (Bild-Download, Key-Validierung, Modellkatalog).
1

Quickstart: Ein-Container-Stack bauen und starten

Der Quickstart läuft als ein Container mit eingebetteter Datenbank; alle persistenten Daten liegen im Bind-Mount data/docker-paperclip.

cd /home/iffi/Develop/paperclip-in-a-bottle

BETTER_AUTH_SECRET="$(openssl rand -hex 32)" \
  docker compose -f docker/docker-compose.quickstart.yml up --build
Zeitplanung: Der erste Build kompiliert den nativen Rust-Runner und dauert je nach Hardware ungefähr 15–25 Minuten. Danach cacht Docker die Schichten, weitere Builds laufen in wenigen Minuten.
Beide Compose-Dateien erwarten zwingend BETTER_AUTH_SECRET. Ohne diese Variable bricht docker compose up sofort mit „BETTER_AUTH_SECRET must be set“ ab.
2

Instanz öffnen und freischalten

  1. Browser: http://localhost:3100 — erreichbar, sobald der Container hochgefahren ist (Healthcheck: curl http://localhost:3100/api/health).
  2. Das Compose läuft als authenticated/private: registrieren bzw. anmelden.
  3. Auf dem Setup-Screen „Claim this instance“ wählen, um das erste Admin-Konto zu beanspruchen. Das ist laut doc/DOCKER.md der Ablauf für frische authenticated/private-Installationen.
Abweichender Port? Zusätzlich PAPERCLIP_PORT=3200 und PAPERCLIP_PUBLIC_URL=http://localhost:3200 setzen — Auth- und Callback-URLs leiten sich von der öffentlichen URL ab.

Mit angepasstem Port starten

PAPERCLIP_PORT=3200 \
PAPERCLIP_PUBLIC_URL="http://localhost:3200" \
BETTER_AUTH_SECRET="$(openssl rand -hex 32)" \
  docker compose -f docker/docker-compose.quickstart.yml up --build
3

Onboarding-Wizard mit OpenCode Go

Das Image wird aus dem lokalen Quellcode gebaut und enthält die neue OpenCode-Go-Verbindung. Im Onboarding läuft es so:

  1. Wizard starten (nach dem Freischalten öffnet sich der Erst-Flow).
  2. Organisation benennen, Agent-Namen vergeben.
  3. Im Schritt „Connect a model“ die dritte Kachel OpenCode wählen — der API-Key-Modus ist dort voreingestellt.
  4. Den OpenCode-Go-API-Key einfügen (nicht OPENAI_API_KEY, nicht ANTHROPIC_API_KEY).
  5. Connect drücken: Der Key wird gegen https://opencode.ai/zen/go/v1/models validiert, als AI-Connection vom Typ opencode-go gespeichert, und der Agent startet auf dem Modell opencode-go/kimi-k2.7-code.
Aspekt Verhalten
Modellvorauswahl Die OpenCode-Kachel startet auf opencode-go/kimi-k2.7-code; weitere opencode-go/…-Modelle sind später in den Agent-Einstellungen wählbar.
Kompatibilität Ein Go-Key läuft nur auf opencode-go/…-Modellen. openrouter/…-Modelle brauchen weiterhin eine OpenRouter-Verbindung.
Nicht abgedeckt Go-Kontingente (5 Stunden / Woche / Monat) zeigt Paperclip derzeit noch nicht an; das Gateway erzwingt die Grenzen.

Alternative: Full Stack mit PostgreSQL 17

cd /home/iffi/Develop/paperclip-in-a-bottle

BETTER_AUTH_SECRET="$(openssl rand -hex 32)" \
  docker compose -f docker/docker-compose.yml up --build
  • Die Datenbank wird per Healthcheck vor dem Server-Start bereitgestellt (condition: service_healthy).
  • Daten landen in den Named Volumes pgdata und paperclip-data.
Dieser Stack bindet Port 5432 am Host. Läuft lokal bereits ein PostgreSQL mit diesem Port, stopt der DB-Container sofort — dann die Port-Zuordnung in der Datei anpassen oder den Quickstart nutzen.

Tagesgeschäft: Logs, Stoppen, Neu-Bauen

# Logs folgen
docker compose -f docker/docker-compose.quickstart.yml logs -f paperclip

# Stoppen (Container weg, Daten bleiben)
docker compose -f docker/docker-compose.quickstart.yml down

# Nach Code-Änderungen: neu bauen und starten
docker compose -f docker/docker-compose.quickstart.yml up --build

# Nur bauen
docker compose -f docker/docker-compose.quickstart.yml build
6

Daten und Reset

Der Quickstart persistiert unter ./data/docker-paperclip (Bind-Mount, in der Compose-Datei relativ zur Datei aufgelöst: ../data/docker-paperclip). Dort liegen die eingebetteten PostgreSQL-Daten, Uploads, der lokale Secrets-Schlüssel und Agent-Workspaces.

# Komplett neu anfangen: Container und Daten löschen
docker compose -f docker/docker-compose.quickstart.yml down
rm -rf data/docker-paperclip

# Danach wie in Schritt 1 neu starten.
Der Reset löscht Unternehmen, Agenten, Verbindungen (auch eine gespeicherte OpenCode-Go-Verbindung) und Uploads unwiderruflich.
7

OpenCode-Go-Key isoliert testen

Vor dem Onboarding lohnt ein Direktaufruf per curl (am Host oder im Container); er benötigt ausgehendes Internet:

curl -sS -H "Authorization: Bearer $OPENCODE_GO_KEY" \
  https://opencode.ai/zen/go/v1/models | head -c 300
Antwortet der Endpunkt mit einer Modellliste (JSON), ist der Key gültig. Ein 401 bedeutet: Key falsch kopiert oder ohne Go/Go-Plus-Abonnement angelegt.

Fehlerbehebung

SymptomUrsache und Ausweg
BETTER_AUTH_SECRET must be set beim Start Secret-Variable fehlt; mit openssl rand -hex 32 erzeugen und dem Aufruf voranstellen.
„The provider rejected this API key.“ bei der Validierung Key falsch kopiert, Abo inaktiv oder fehlende Internetverbindung aus dem Container. Direkten Test aus Schritt 7 nutzen.
Schreibrechte-Probleme in data/docker-paperclip Bind-Mount/UID-Konflikt. Neu bauen mit --build-arg USER_UID=$(id -u) und --build-arg USER_GID=$(id -g); der Entrypoint gleicht UID/GID im Container an.
Port 3100 belegt PAPERCLIP_PORT=… setzen (Quickstart) und den PAPERCLIP_PUBLIC_URL auf den neuen Port mitschreiben.
Port 5432 belegt (Full Stack) Lokales PostgreSQL stoppen oder die Port-Zuordnung in docker/docker-compose.yml ändern.
Build bricht im Rust-Teil ab Cache-Prüfung: docker builder prune erwägen und erneut bauen. Details zum Runner-Build-Cache stehen in doc/DOCKER.md.
Instanz antwortet nicht Logs mit logs -f prüfen und den Health-Endpoint /api/health ansprechen.
